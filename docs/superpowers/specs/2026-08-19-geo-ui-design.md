# Geo UI: управление списками на роутере

Дата: 2026-08-19. Роутер: Keenetic Netcraze Ultra, Entware, `root@192.168.117.1`.
Источник правды для списков: `/opt/root/geo/` на роутере (не git).

## Цель

Веб-интерфейс в LAN: править группы доменов, geosite/geoip-тегов и своих IP/CIDR.
После успешного сохранения сразу применяется `geo-update.sh -n` (без повторной загрузки `.dat`).

## Вне скоупа (v1)

- Пароль / HTTP Basic
- Слушание WAN / `0.0.0.0`
- git commit/push
- Новые ipset-имена кроме `blocked-sites` и `only-ru`
- IPv6
- Сборка Vue на роутере

## Позже (не v1)

- Диагностика: `geo-why` и «куда уйдёт IP» — в UI будет, отдельной версией.

## Архитектура

```
Браузер (LAN)
    -> Python Flask :8787, bind = LAN IPv4 (определяется при старте)
         GET  /          Vue dist (собрано на ПК)
         /api/...        JSON + поток лога apply
         пишет /opt/root/geo/geo.d/<slug>.conf
         flock -> geo-update.sh -n (stdout/stderr в UI)
```

Репозиторий: `scripts/geo-ui/` (backend Python + frontend Vue/Vite).
На роутере: `/opt/root/geo-ui/` (app + `dist/` + venv/пакеты) и `/opt/etc/init.d/S80geo-ui`.

Flask не слушает `0.0.0.0` и не биндится на WAN/WG. При старте берёт IPv4 LAN-моста `br0` (`ip -4 -o addr show dev br0`). Если `br0` нет или без адреса — первая private IPv4 не loopback, не `nwg0`, не интерфейс default-route в сторону WAN. Порт 8787, смена порта — только явно в init.d.

## Данные: группа = файл

Каталог: `/opt/root/geo/geo.d/*.conf` (как сейчас, `common.conf` делает `include geo.d/*.conf`).

- Один файл = одна группа.
- Заголовок файла — комментарии до первой секции `[...]`:
  - **название** — первая строка-комментарий; если её нет — имя файла без `.conf`;
  - **описание** — остальные строки-комментарии заголовка; может отсутствовать.
- Переименование меняет первую строку комментария; правка описания — остальные. Имя файла не меняется.
- Создание группы: файл `geo.d/<slug>.conf`. `slug` — из названия (`[a-z0-9-]+`), при коллизии суффикс `-2`, `-3`, …
- Удаление группы: удаление файла (вместе с записями).
- Существующие `custom.conf`, `geosite.conf`, `geoip.conf` — обычные группы: первая строка заголовка = название, остальные = описание.

Пример:

```
# PlayStation / Sony
# Домены и теги Sony / PSN

[blocked-sites]
playstation.com
geosite:sony
1.2.3.4
10.0.0.0/8

[only-ru]
myip.ru
```

Типы строк в секции:

| Строка | Смысл | Куда попадает |
|---|---|---|
| `geosite:<тег>` | тег geosite | dnsmasq `*-site` |
| `geoip:<тег>` | тег geoip | ipset `*-ip` |
| IPv4 или IPv4/CIDR | свой адрес | ipset `*-ip` |
| иначе домен (как сейчас, в т.ч. TLD вроде `playstation`) | ручной домен | dnsmasq `*-site` |

Префикса `ip:` нет. Разбор: сначала `geosite:`/`geoip:`, затем IPv4/CIDR, затем текущие `DOMAIN_RE`/`TLD_RE`.

В одном файле можно смешивать все типы и обе секции `[blocked-sites]` / `[only-ru]`.

Порядок записей в файле сохраняется при правке (не сортировать без нужды). Дубликаты в генерации по-прежнему схлопывает `geo-update.sh`.

## Изменения `geo-update.sh`

Сейчас заливка `*-ip` делается только если есть geoip-теги (`[ -s "$cf" ] || continue`). Это ломает «голые» CIDR.

Нужно:

1. Распознавать IPv4/CIDR в парсере и писать их в `$TMP/$set.cidrs` (отдельно от тегов).
2. Собирать `*-ip` из geoip-тегов **и** ручных CIDR.
3. Делать swap `*-ip`, если итоговый список CIDR непустой, даже без единого `geoip:` тега.
4. Поведение остальных строк не менять.

## Backend (Python / Flask)

Пакеты на роутере: `python3` + Flask (opkg `python3-flask`, если нет — pip в `/opt/root/geo-ui`).

Модули:

- `confio` — чтение/запись `geo.d/*.conf`. Сохраняется блок комментариев до первой секции (первая строка = title, остальные = description); комментарии внутри секций при записи из UI отбрасываются.
- `apply` — `flock` на `/opt/root/geo/geo-ui.lock`, затем `/opt/root/geo/geo-update.sh -n`. stdout и stderr процесса читаются построчно (как в консоли, без буферизации пачками) и отдаются в UI. Код выхода — в конце потока.
- `tags` — список тегов из `geosite.dat` / `geoip.dat` через `geoview` (кэш в памяти на время процесса).
- `app` — статика `dist/` + JSON API + поток лога.

API (все мутации под flock вместе с apply):

- `GET /api/groups` — список групп (`slug`, `title`, `description`) + коллизии.
- `GET /api/groups/<slug>` — группа целиком (заголовок + записи).
- `GET /api/groups/<slug>/entries` — только записи группы.
- `POST /api/groups` `{ "title": "...", "description": "..." }` (`description` опционально)
- `PATCH /api/groups/<slug>` `{ "title": "...", "description": "..." }` — поля по отдельности, что передано.
- `DELETE /api/groups/<slug>`
- `POST /api/groups/<slug>/entries` `{ "set": "blocked-sites"|"only-ru", "value": "..." }`
- `PATCH /api/groups/<slug>/entries/<id>` — смена сета и/или перенос в другую группу (`set`, `group`).
- `DELETE /api/groups/<slug>/entries/<id>`
- `GET /api/tags?type=geosite|geoip` — подсказки тегов.
- `GET /api/status` — код последнего apply; опционально число элементов `*-site`/`*-ip`.

GET и ошибки валидации (400/404) — `application/json`. Мутации после успешной записи файла — `text/event-stream`: события `log` (строка как в консоли) и финальное `done` `{ "exit": <code> }`. `geo-update` по-прежнему пишет `geo-update.log` через свой `tee`. Если `exit != 0`: файлы уже новые, отката нет.

`id` записи: индекс в списке записей группы (0-based, после парсинга). При переносе запись удаляется из исходного файла и добавляется в конец целевой секции.

Валидация до записи: известный сет, непустой value, формат домена/тега/CIDR. Неизвестный geosite/geoip-тег — предупреждение (как в `geo-update`), запись сохраняется.

## Коллизии

Точное совпадение `value` во всех группах: trim, домены и теги в lower-case, IP/CIDR как строка после trim (без нормализации префикса).

UI при вводе и в списке:

- уже есть в группе X, сет Y;
- то же значение в `blocked-sites` и `only-ru` (на роутере победит `only-ru`).

Подсветка не блокирует сохранение. Пересечение CIDR «на глаз» (частичное покрытие geoip) в v1 не считается.

## Frontend (Vue 3 + Vite)

Сборка на ПК: `npm run build` → `dist/`. На роутер копируется только `dist/`.

Язык UI: русский.

Визуал зафиксирован в `scripts/geo-ui/frontend/UI.md` (2026-08-20):

- Keenetic-светлая; группы слева; лог apply снизу, высота тянется, можно скрыть или на весь экран.
- Записи — две flex-карточки секций (`blocked-sites` / `only-ru`), на широком две колонки.
- Добавление — пустая строка внизу секции. Кнопки «+ Секция» нет; в коде цикл по `SETS`.
- Коллизии: жёлтая подсветка, сохранение можно.

Поведение:

- Список групп: `title`, при отсутствии заголовка — slug/имя файла; `description` если есть.
- Группа: секции записей, добавление, удаление, перенос в другую группу / другой сет.
- Создание / переименование (title) / правка description / удаление группы.
- Панель лога: строки apply появляются так же, как в консоли, пока идёт `geo-update.sh`.
- Подсказки тегов geosite/geoip с `/api/tags`.

## Ошибки

- Невалидная строка → 400, файл не пишем.
- Нет файла группы → 404.
- Параллельные запросы и cron `geo-update` → `flock`.
- Не удалось определить LAN IP → сервис не стартует, ошибка в лог init.d (не fallback на `0.0.0.0`).
- Порт занят → fail сервиса, не молча другой порт.

## Проверка

1. Unit на ПК: `confio` round-trip (заголовок, две секции, смесь типов, CIDR без `ip:`).
2. `geo-update.sh -n` с файлом, где есть только `1.2.3.4/24` в `[blocked-sites]` без `geoip:` → адрес в `blocked-sites-ip`.
3. На роутере: UI на `http://<br0-ip>:8787`, создать группу, добавить домен, тег, CIDR → в панели лог как в консоли, exit 0, запись в файле, ipset/dnsmasq обновлены.
4. Дубликат подсвечен, сохранить можно.
5. С WAN UI не открывается (bind только LAN IP). Смена адреса `br0` + рестарт сервиса — новый bind без правки конфига.
6. Группа без `#` в заголовке показывается именем файла; с одной `#` строкой — title, без description.
7. `S80geo-ui stop` / `start` после ребута.

## Раскладка в репо

```
scripts/geo-ui/
  backend/          Flask, confio, apply
  frontend/         Vue 3 + Vite
  init.d/S80geo-ui
scripts/geo/geo-update.sh   # парсер CIDR + заливка *-ip
```
